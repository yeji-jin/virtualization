# TanStack Virtual로 배우는 리스트 가상화

실습 코드: [virtualization-library-lab.tsx](./virtualization-library-lab.tsx)  
실습 주소: `/demo/virtualization-library`  
이전 노트: [라이브러리 없는 버전](../virtualization/라이브러리없는버전.md)

## 1. 이번 실습에서 달라진 것

가상화의 원리는 그대로다. 전체 배열 중 화면 주변의 행만 DOM에 만들고, 전체 스크롤 공간을 유지한다.

직접 구현에서는 scrollTop으로 인덱스 범위를 계산했다. 이번에는 `@tanstack/react-virtual`의 `useVirtualizer`가 스크롤과 크기를 관찰하고 필요한 행의 배치 정보를 제공한다.

현재 설치 버전은 `@tanstack/react-virtual` 3.14.13이다. 이 노트의 내부 구현 설명은 현재 설치된 소스를 기준으로 하며, 버전이 바뀌면 세부 구현은 달라질 수 있다.

| 라이브러리가 담당 | 우리가 담당 |
|---|---|
| 스크롤 위치와 컨테이너 크기 관찰 | 데이터 생성 또는 API 요청 |
| 렌더링할 행 범위와 overscan 계산 | 행 안에 표시할 콘텐츠 |
| 행 크기와 시작 좌표 계산 | HTML 구조와 CSS 배치 |
| 전체 스크롤 크기 계산 | 목록의 디자인과 접근성 구성 |
| 원하는 인덱스로 스크롤 | 검색·필터·정렬·페이지네이션 정책 |

라이브러리가 데이터를 다운로드하거나 배열 메모리를 줄여주는 것은 아니다. 이 실습도 mock data 전체를 메모리에 보관한다.

## 2. TanStack Virtual이 headless라는 의미

완성된 목록 컴포넌트를 주기보다, 목록을 만드는 데 필요한 계산과 동작을 제공한다. 그래서 `<useVirtualizer />`처럼 화면에 넣는 것이 아니라 훅을 호출한다.

```tsx
const rowVirtualizer = useVirtualizer({ /* 계산에 필요한 설정 */ });
```

이후 우리가 직접 div를 만들고 반환받은 좌표를 스타일에 연결한다.

```text
라이브러리: 인덱스 10인 행의 시작 위치는 640px이다.
우리 코드: 그 위치를 translateY에 적용하고 제목과 카테고리를 그린다.
```

목록 구조까지 제공하는 예로 React Virtuoso의 가상 목록 컴포넌트, react-window의 `List`가 있다. 여기서 UI 제공은 완성된 카드 디자인까지 제공한다는 뜻이 아니다. 행 내용과 디자인은 개발자가 작성하며, 라이브러리에 따라 배치 스타일을 연결하는 작업도 필요하다.

## 3. 컴포넌트 구조

```text
page.tsx
  └─ VirtualizationLibraryLab
       ├─ 데이터와 실험 설정 관리
       ├─ LibraryList
       │    ├─ useVirtualizer
       │    ├─ 범위·행 개수 표시와 이동 버튼
       │    └─ 스크롤 컨테이너와 행 렌더링
       └─ 기존 코드와의 대응표·학습 설명
```

`page.tsx`는 페이지와 메타데이터를 제공한다. 상호작용을 처리하는 파일은 `"use client"`로 시작한다.

## 4. 주요 변수와 함수

### 공통 데이터와 표시 값

| 이름 | 의미 |
|---|---|
| `ROW_HEIGHT` | 행의 고정 높이 64px |
| `format(value)` | `10000`을 `"10,000"`처럼 표시용 문자열로 변환 |
| `buttonClass` | 공통 버튼 스타일 |
| `createItems(count)` | 이전 실습과 같은 규칙으로 가짜 데이터를 생성 |
| `Item` | 생성한 데이터 한 개의 타입 |
| `comparisons` | 페이지 하단의 비교표에 사용할 설명 배열. 가상화 연산과 무관 |

### VirtualizationLibraryLab의 상태

| 이름 | 초기값 | 역할 |
|---|---|---|
| `count` | 1000 | 전체 데이터 개수 |
| `overscan` | 3 | 화면 앞뒤에 추가할 행 수 |
| `viewportHeight` | 384 | 스크롤 컨테이너의 CSS 높이 |
| `run` | 0 | 목록을 다시 마운트하기 위한 번호 |
| `items` | 생성된 배열 | 모든 원본 데이터 |

각 `setCount`, `setOverscan`, `setViewportHeight`, `setRun`은 대응하는 상태의 변경 함수다.

```tsx
const items = useMemo(() => createItems(count), [count]);
```

일반적인 재렌더링에서 count가 같으면 계산 결과를 재사용한다. 개발 모드에서는 순수성 확인 등의 이유로 계산이 추가 실행될 수 있다. useMemo는 가상화와 별개의 계산 재사용 기능이다.

### LibraryList 내부

| 이름 | 역할 |
|---|---|
| `viewport` | 실제 스크롤 DOM에 연결하는 ref |
| `getItemKey` | 인덱스를 받아 해당 데이터의 안정적인 ID 반환 |
| `rowVirtualizer` | 가상화 상태와 메서드를 제공하는 인스턴스. 데이터 배열이 아님 |
| `virtualRows` | 현재 렌더링할 행들의 배치 정보 배열 |
| `virtualRow` | map으로 순회 중인 행 하나의 배치 정보 |
| `item` | `items[virtualRow.index]`로 찾은 실제 데이터 |
| `firstRow` | 현재 렌더링할 첫 행의 배치 정보 |
| `lastRow` | 현재 렌더링할 마지막 행의 배치 정보 |

### virtualRow의 주요 속성

| 속성 | 의미 | 예 |
|---|---|---|
| `index` | 전체 현재 데이터 배열에서의 인덱스 | 7 |
| `key` | 해당 항목의 식별자 | 현재 데이터에서는 8 |
| `start` | 행이 시작하는 세로 좌표(px) | 448 |
| `size` | 행의 높이(px) | 64 |
| `end` | 행의 끝 좌표(px) | 512 |

**기존 코드의 start/end는 배열 인덱스 경계였고, virtualRow.start/end는 픽셀 좌표다.** 이름이 비슷해도 단위가 다르다.

## 5. 처음 페이지를 열었을 때의 흐름

### ① 전체 데이터 준비

부모가 초기 상태를 만들고 createItems로 1,000개를 생성한다.

### ② 자식에게 전달

```tsx
<LibraryList
  key={`${count}-${run}`}
  items={items}
  overscan={overscan}
  viewportHeight={viewportHeight}
/>
```

### ③ 스크롤 요소와 식별자 준비

```tsx
const viewport = useRef<HTMLDivElement>(null);
const getItemKey = useCallback((index: number) => items[index].id, [items]);
```

처음 ref는 null이다. DOM이 연결되면 viewport.current가 실제 요소를 가리킨다. ref 연결 자체는 useState처럼 재렌더링을 요청하지 않는다. 라이브러리가 마운트 이후 요소를 읽고 관찰을 연결한다.

useCallback은 items가 같을 때 getItemKey 함수 참조를 재사용한다. ID를 생성하거나 데이터 자체를 캐시하는 함수가 아니다.

### ④ useVirtualizer 설정

```tsx
const rowVirtualizer = useVirtualizer({
  count: items.length,
  getScrollElement: () => viewport.current,
  estimateSize: () => ROW_HEIGHT,
  getItemKey,
  overscan,
});
```

| 옵션 | 라이브러리에 알려주는 내용 |
|---|---|
| `count` | 항목이 총 몇 개인지 |
| `getScrollElement` | 어떤 DOM 요소를 관찰할지 |
| `estimateSize` | 아직 측정값이 없을 때 사용할 예상 크기 |
| `getItemKey` | 항목을 어떻게 식별할지 |
| `overscan` | 화면 바깥의 여유분을 얼마나 둘지 |

getScrollElement는 함수를 전달하므로 라이브러리가 필요할 때 최신 viewport.current를 읽을 수 있다.

현재는 고정 높이 구현이다. estimateSize가 반환하는 64와 실제 CSS 행 높이가 같도록 맞춘다. **estimateSize 자체가 CSS를 설정하는 것은 아니다.**

### ⑤ 필요한 행의 배치 정보 읽기

```tsx
const virtualRows = rowVirtualizer.getVirtualItems();
```

이 배열은 제목·카테고리 데이터가 아니라 index, start, size, key 등의 정보다. 스크롤 요소 측정 전에는 비어 있을 수 있고, 연결·측정 후 필요한 행이 나타난다.

### ⑥ 전체 스크롤 공간 생성

```tsx
<div
  style={{
    height: rowVirtualizer.getTotalSize(),
    position: "relative",
  }}
>
```

1,000개 × 64px이면 전체 높이는 64,000px이다. 적은 수의 행만 DOM에 있어도 이 공간 덕분에 전체 목록 길이만큼 스크롤한다.

### ⑦ 원본 데이터 조회와 배치

```tsx
virtualRows.map((virtualRow) => {
  const item = items[virtualRow.index];
  // item으로 콘텐츠를, virtualRow로 위치와 크기를 정한다.
});
```

```tsx
style={{
  position: "absolute",
  top: 0,
  left: 0,
  width: "100%",
  height: virtualRow.size,
  transform: `translateY(${virtualRow.start}px)`,
}}
```

index 7이라면 items[7]에서 8번째 데이터를 읽고, 현재 고정 높이 조건에서는 448px 위치에 배치한다. ID로 위치를 계산하지 않으므로 기존 예제의 `item.id - 1` 전제도 필요 없다.

## 6. 스크롤하면 어느 부분에서 업데이트할까?

직접 구현에서는 다음 코드를 작성했다.

```tsx
onScroll={(event) => setScrollTop(event.currentTarget.scrollTop)}
```

라이브러리 버전의 연결 지점은 다음 옵션이다.

```tsx
getScrollElement: () => viewport.current
```

이 함수 자체가 이벤트 핸들러는 아니다. 관찰할 DOM을 제공하면 라이브러리가 내부에서 이벤트를 구독한다.

```text
직접 구현
사용자 스크롤
 → onScroll
 → setScrollTop
 → 컴포넌트 재렌더링
 → floor/ceil로 start/end 계산
 → slice로 데이터 선택

라이브러리 구현
사용자 스크롤
 → 라이브러리 내부 스크롤 이벤트 처리
 → 위치와 필요한 범위 갱신
 → 필요한 경우 React 재렌더링 유도
 → LibraryList 함수 재실행
 → getVirtualItems로 현재 배치 정보 읽기
 → 행 렌더링
```

**getVirtualItems가 스크롤을 감시하거나 React 갱신을 시작하는 것은 아니다.** 이 메서드는 렌더링 시 필요한 배치 정보를 얻는 데 사용한다. 관찰과 React 업데이트 연결은 useVirtualizer 내부에 있다. 모든 스크롤 픽셀마다 반드시 React 렌더링이 발생한다는 의미도 아니다.

설치된 소스에서 직접 확인할 수 있는 부분:

- `node_modules/@tanstack/virtual-core/src/index.ts`: scroll 이벤트 등록, observeElementOffset, getScrollElement로 요소 연결.
- `node_modules/@tanstack/react-virtual/src/index.tsx`: 내부 onChange에서 rerender 호출, useVirtualizer의 기본 관찰 함수 연결.

내부의 onChange는 라이브러리의 변경 알림이다. JSX에서 우리가 작성한 onScroll과 역할이 연결되지만 동일한 API는 아니다.

## 7. 질문: getItemKey는 그냥 식별자라서 실질적 기능이 없을까?

식별하는 것 자체가 중요한 기능이다. 인덱스는 위치이고 ID는 항목의 정체성이다.

```text
정렬 전: index 0 → 사과, id A
정렬 후: index 0 → 포도, id C
```

라이브러리는 안정적인 키를 통해 항목별 크기 캐시 등을 관리할 수 있다. 이 코드에서는 반환된 virtualRow.key를 React key로도 전달한다.

```tsx
key={virtualRow.key}
```

기본적으로 인덱스를 키로 사용하는 것과, 데이터 ID를 키로 사용하는 것은 추가·삭제·재정렬 시 차이가 생긴다. ID는 항목마다 고유하고 같은 항목에 대해 안정적이어야 한다.

다만 안정적인 key가 있다고 DOM에서 제거된 행의 로컬 상태까지 영구 보관되는 것은 아니다. 행이 언마운트되면 입력값 등의 상태 보관 전략을 별도로 고려해야 한다.

## 8. 질문: firstRow와 lastRow는 무엇일까?

```tsx
const firstRow = virtualRows[0];
const lastRow = virtualRows[virtualRows.length - 1];
```

현재 선택된 배치 정보 배열의 처음과 끝을 꺼낸다. 예를 들어 index 7~18이 선택됐다면:

```text
firstRow.index = 7
lastRow.index = 18
화면 표시 = 렌더링 범위: 8–19번
```

사용자에게 1부터 세는 번호를 보여주므로 각각 +1을 한다. 이것은 실습 화면 설명용이며 가상화 계산을 수행하는 값이 아니다. overscan을 포함하므로 실제 눈에 보이는 첫 행·마지막 행과 다를 수 있다.

빈 배열이면 둘 다 undefined일 수 있으므로 `firstRow && lastRow`로 확인한 뒤 표시한다.

## 9. 질문: absolute가 가상화의 필수 조건일까?

필수는 아니다. 가상화의 핵심은 필요한 행만 만들고, 생략된 부분의 공간을 유지하는 것이다. 현재 구현은 각 행을 좌표로 배치하는 방법을 택했다.

absolute로 일반 흐름에서 분리하고 top 0이라는 공통 기준에서 translateY만큼 이동한다. **translateY는 스크롤을 이동시키지 않고 행 위치를 지정한다.**

TanStack Virtual은 계산을 제공하므로 이 배치를 우리가 작성한다. 현재 코드에서 absolute만 제거하면 일반 흐름의 위치에 이동량이 추가되어 배치가 틀어진다.

### 대안: 위아래 빈 공간 방식

전체 1,000개, 행 50px, 101~110번째만 렌더링한다고 가정한다.

```text
위쪽 빈 div: 100 × 50 = 5,000px
실제 행 10개: 10 × 50 = 500px
아래 빈 div: 890 × 50 = 44,500px
전체 높이: 50,000px
```

101번째 앞에 원래 있었던 100개 행을 높이 5,000px짜리 빈 요소 하나로 대체한다. 그 뒤에 일반 흐름으로 행을 쌓으면 첫 행이 자연스럽게 5,000px에서 시작한다. scrollTop이 5,000이면 앞의 빈 공간을 이미 지나왔으므로 실제 행이 보인다.

다음은 고정 높이의 개념 예제이며 현재 코드를 교체한 것은 아니다.

```tsx
const topSpace = start * ROW_HEIGHT;
const bottomSpace = (items.length - end) * ROW_HEIGHT;

<div
  style={{ height: VIEWPORT_HEIGHT, overflowY: "auto" }}
  onScroll={(event) => setScrollTop(event.currentTarget.scrollTop)}
>
  <div aria-hidden="true" style={{ height: topSpace }} />
  {items.slice(start, end).map((item) => (
    <div key={item.id} style={{ height: ROW_HEIGHT, boxSizing: "border-box" }}>
      {item.title}
    </div>
  ))}
  <div aria-hidden="true" style={{ height: bottomSpace }} />
</div>
```

start/end를 스크롤에 맞춰 계산하는 로직은 여전히 필요하다. 스크롤하면 위쪽·아래쪽 공간의 크기가 바뀌고, 전체 높이는 유지된다. paddingTop/paddingBottom으로 공간을 확보하는 방법도 있다.

absolute가 없어도 실제 높이 계산은 필요하므로 유동 높이의 어려움까지 없어지는 것은 아니다. 라이브러리가 목록 컴포넌트를 제공하는지와 내부에서 absolute를 사용하는지도 별개의 문제다.

## 10. 직접 구현과 한눈에 비교

여기서 직접 구현은 이전 페이지의 가상화 모드를 뜻한다. 전체 행을 렌더링하는 일반 모드와 구분한다.

| 역할 | 직접 구현 | TanStack Virtual 버전 |
|---|---|---|
| 스크롤 요소 | viewport ref | 동일 |
| 스크롤 감지 | JSX onScroll | 훅 내부에서 이벤트 연결 |
| 위치 저장 | scrollTop 상태 | 라이브러리 내부 관리 |
| 범위 계산 | floor/ceil, start/end | 라이브러리가 계산 |
| 필요한 행 가져오기 | items.slice(start, end) | getVirtualItems의 index로 items 조회 |
| 전체 높이 | items.length × ROW_HEIGHT | getTotalSize() |
| 행 높이 | ROW_HEIGHT | virtualRow.size |
| 행 시작 좌표 | (item.id - 1) × ROW_HEIGHT | virtualRow.start |
| 이동 버튼 | 픽셀 계산 후 scrollTo | scrollToIndex |
| 영역 크기 변경 | 계산값과 실제 높이를 직접 맞춤 | 요소 크기 관찰에 따라 범위 갱신 |
| 행 내부 UI | 직접 작성 | 직접 작성 |
| 데이터 다운로드 | 별도 구현 | 별도 구현 |

둘 다 같은 원리이므로 라이브러리를 썼다는 이유만으로 항상 더 빠르다고 단정하지 않는다. 주요 이점은 직접 관리해야 하는 관찰·계산·갱신 로직을 줄이는 것이다.

## 11. 설정과 버튼을 조작하면

| 조작 | 흐름 |
|---|---|
| 데이터 개수 변경 | count 변경 → 배열 재생성 → key 변경 → 목록 새로 마운트 |
| overscan 변경 | 옵션 변경 → 렌더링 범위 갱신 |
| 영역 높이 변경 | CSS 높이 변경 → 라이브러리 크기 관찰 → 범위 갱신 |
| 다시 마운트 | run 증가 → key 변경 → 목록 및 스크롤 초기화 |
| 처음·중간·마지막 | scrollToIndex 호출 → 스크롤 이동 → 범위 갱신 |

```tsx
rowVirtualizer.scrollToIndex(0, { align: "start" });
rowVirtualizer.scrollToIndex(items.length - 1, { align: "end" });
```

start는 행을 영역 위쪽에, end는 아래쪽에 맞추는 정렬 옵션이다. 배열 인덱스로 목적지를 지정하므로 픽셀 위치를 직접 계산할 필요가 없다.

key는 `${count}-${run}`이다. overscan과 viewportHeight는 key에 없으므로 이 값을 바꿔도 목록 자체를 새로 마운트하지 않는다. 다시 마운트 버튼도 count가 같으면 전체 데이터까지 새로 생성하는 것은 아니다.

## 12. 고정 높이와 동적 높이를 구별하기

현재 행은 64px로 고정이다. 컨테이너 높이 슬라이더가 동작한다고 행의 동적 높이까지 구현된 것은 아니다.

내용마다 높이가 달라지게 확장하려면 보통 다음 작업이 필요하다.

1. 고정 height를 해제해 콘텐츠가 실제 높이를 가지도록 한다.
2. 행에 data-index를 제공하고 measureElement를 연결한다.
3. 라이브러리가 예상 크기를 실제 측정 크기로 보정하도록 한다.
4. 줄바꿈, 이미지 로딩, 화면 너비 변경, 스크롤 위치 변화를 확인한다.

padding과 border를 포함한 실제 외곽 크기가 배치에 반영되어야 한다. 현재 코드는 컨테이너 border를 바깥 요소에 두고, 행은 border-box 기준 크기를 사용한다. margin이나 별도 gap을 임의로 추가하면 계산과 실제 배치가 달라질 수 있다.

## 13. 그 밖의 코드 읽기 포인트

- `"use no memo"`: React Compiler가 해당 함수를 자동 메모화하지 않도록 하는 지시문이다. 일반 React 재렌더링이나 개발자가 작성한 useMemo/useCallback을 끄는 것은 아니다. 이 프로젝트는 Compiler를 명시적으로 활성화하지 않았으며, 설치된 ESLint에서는 호환성 경고가 계속 표시될 수 있다.
- `aria-posinset={virtualRow.index + 1}`: 현재 전체 목록에서의 1부터 시작하는 순번.
- `aria-setsize={items.length}`: 전체 항목 수.
- `data-list`, `data-row`: DevTools에서 목록과 행을 찾기 위한 표시.
- `virtualRows.length`: 행 DOM의 개수이며 내부 span, p 등을 포함한 모든 노드 수는 아니다.

## 14. 복습과 실험

1. useVirtualizer 옵션과 이전의 ROW_HEIGHT, scrollTop, overscan을 연결해본다.
2. 데이터 1,000개에서 10,000개로 바꿔도 행 DOM 수가 크게 증가하지 않는지 본다.
3. 중간으로 이동해 firstRow/lastRow가 바뀌는 것을 확인한다.
4. overscan 0과 10을 비교한다.
5. 영역 높이를 바꾸면 JSX에 onScroll이 없어도 범위가 갱신되는지 확인한다.
6. 직접 구현과 경계의 행 수가 조금 다를 수 있음을 기억한다. 실제 영역 치수와 경계 처리 방식이 원인이 될 수 있다.
